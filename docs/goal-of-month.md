# Goal of the Month

The monthly competition is owned by `src/lib/goal-of-month/calendar.ts` and `community.ts`. A goal qualifies by the fixture's London match month, not its upload or nomination date. Nomination windows close at the start of the following 6th; voting runs through the 12th, and closed-round winners appear from the 13th. All boundaries use Europe/London including daylight-saving changes. During days 1–5 both the previous and current month can accept nominations.

The public `/goal-of-the-month` page, the captain/player dashboard promotion and the homepage use this source. `GoalNomineeCard` shows the fixture's existing video links with the nominated goal number, team, scorer and nomination count. YouTube footage plays on demand; other HTTPS providers open externally. A link can contain match highlights rather than an isolated goal. No video cutting or fabricated goal timestamps are added. The page shows current nominees; dashboards show up to three nominees or finalists and the latest monthly winner. Both refresh on return/focus; successful nominations refresh the competition immediately.

One fixture/goal has one candidate regardless of nomination count. Account and goal advisory locks protect the three-per-month nomination allowance and duplicate identity. The six highest nomination counts form the ballot; nominations are closed by then. Voting records one changeable vote per account/month. Ties use nominations, then earliest candidate and stable id. Zero votes means no player-voted winner. Only verified player/captain accounts or signed-in admins may nominate or vote, using their own account rather than a supplied user id. Public readers see only display data, not nominator identities.

Monthly nominations can be reviewed under Admin SIXFL TV > Player nominations & voting, now redirected to `/admin/sixfl-tv/goal-of-month`. Admins can correct scorer names and remove/restore a nominee without deleting its nominations or votes. The weekly archive and weekly manual editor remain for historical awards.

The migration creates new monthly records and a single transition row; it does not transform, delete or relabel weekly nominations/votes/winners. The current weekly round may finish until its original Sunday/Tuesday deadlines, then the legacy API rejects new weekly participation. Original weekly links lead to the monthly competition unless `legacy=1` is requested. Existing weekly winners remain clearly weekly. No outbound notification is triggered, no existing template edit is overwritten, and no live vote or nomination is used for testing. This rollout adds no automatic reminder blast.

Verification includes isolated PostgreSQL migration replay and concurrency tests, real API boundary/legacy cut-off tests, shared card rendering, real React interaction tests with fake network responses, production-prepared source TypeScript and existing homepage browser tests. These are separate from a real signed-in production nomination or video-provider playback check, which must not be claimed without actually performing them.
