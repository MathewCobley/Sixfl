# Individual payment warning history

Admin Payments previously only displayed PlayerMatchFee.lastChasedAt, an ordinary request/chase timestamp that the separate individual-warning service does not change. The per-fee card now reads the latest PLAYER_MATCH_FEE_WARNING dispatch using the exact fee ID and shows channel, actual state, recorded event time and the chosen deadline. Existing warnings are read without migration, backfill or resending. Ordinary chase timestamps and actions remain separate.

`src/lib/payments/player-payment-warning-history.ts` owns read-only selection and display-state interpretation for both the batched visible-card query and the ten-entry detail history. `PlayerPaymentWarningStatus` is the shared native component. Failed provider callbacks take precedence over a populated sentAt; queued or processing messages are never described as sent, and provider submission is not called confirmed receipt. Metadata returned to the component is restricted to the deadline; no customer message body or contact lookup is necessary.

Successful warning confirmation invalidates both Admin Payments and the warning page. Both views have a native Refresh warning status button that only refreshes server data; no timer, send action or queue processor is invoked. The per-fee status links to the exact warning record in the admin delivery queue and the matching fee history. Both pages retain their existing admin guards.

Tests exercise the real query/projection and React status component with isolated I/O, including multiple fees for one person, older dispatches, queued/sent/failed states, missing/malformed fields, source scoping, access guards, safe output and the main list binding. The full-prebuild CI removes the main status component as a negative control and must fail. Mobile/desktop browser tests check real badges, exact links, refresh-only behaviour and overflow. The original individual-warning workflow continues to protect preview, confirmation and both provider gates with its disposable PostgreSQL tests. No production sends, balances or fee records are changed by this display correction.
