# Audited result overturns

## Administrator workflow

Open **Admin → Fixtures → the recorded result → Overturn result**. An existing captain complaint also links to this control from **Admin → Results**. Only a real stored ADMIN can read or save a decision. The page does not apply a decision on opening.

The current playing score is preserved automatically; do not edit it into the award first. Choose the team receiving the 3–0 win, a category, a private reason, an evidence reference and the rules applicable when the fixture occurred. Preview both scores, then explicitly confirm. An existing saved decision is read-only. Ordinary result editing cannot erase the original or the award. Reconsideration of a saved decision needs a separately audited change, not a normal score correction.

This feature does not decide any particular complaint, send messages, resolve existing disputes, levy charges, refund fees or rewrite published articles. Notify the captains separately and resolve the complaint record after reviewing it. The reason/evidence/rules are administrator-only; public and captain/player pages receive only score metadata and the neutral decision label.

## Two score meanings

`MatchResult.homeScore/awayScore` remain the official competition result. `getLeagueStandings()` continues to use them for points, goals and form; there is no alternative standings calculator.

`originalHomeScore/originalAwayScore` plus `overturnedAt` identify a genuine recorded overturn. The shared `getOnPitchResult()`/`useOnPitchResults()` projection feeds V2/V3 predictive histories, name-aware histories, first-match eligibility, historical recovery, prediction accuracy and back-testing. The ordinary 3–0 score is not treated as a forfeit without the explicit marker. A marked decision without reliable originals is not predictive evidence; it never falls back to the administrative award. Existing frozen prediction snapshots are not regenerated by a decision. Original result-entry time is retained to preserve chronological back-test cutoffs.

The public notice says **Awarded · Result overturned by SIXFL**, shows the original playing score, and explains that the official award counts in the table. Scorer/assist editing and completion prompts use playing goals, not fictional awarded goals. A fresh automated matchnight report excludes an overturned fixture for explicit editorial review, as with other administrative exceptions; already published snapshots remain untouched.

## Integrity and rollout

The additive migration creates an immutable private `MatchResultOverturn` record and nullable public score metadata. It changes no existing scores. The database validates the original scores, fixture/team identity and ADMIN actor, and applies the award atomically in the same insert transaction. Triggers protect original score/provenance and awarded score from ordinary Prisma/referee/raw SQL updates and deletions. Abandonment/no-show fixtures use their separate process and cannot enter this one.

The API requires same-origin JSON, a real authenticated ADMIN, a signed ten-minute preview bound to actor and fixture, a current snapshot and explicit confirmation. Row locks plus a unique decision nonce prevent stale/racing/double submissions. Only the confirmation writes. A lost-response retry of the same valid preview returns the existing decision once.

The new CI workflow applies the actual migration to an isolated pre-migration PostgreSQL database, tests core decisions and concurrency, checks actual central standings and playing-score predictive invariance, exercises endpoint authorization, runs the complete source preparation, type-check and build, and tests the real form/public notice at desktop/mobile widths. No production credentials or customer actions are used.
