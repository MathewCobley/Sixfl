# Admin team match-report badges

Admin Teams and the individual admin team heading share `TeamMatchReportBadge` and `getAdminTeamMatchReportActivity`. A small clipboard **Match reports · N** badge indicates saved scorers, assists, Player of the Match or captain-recorded ratings on completed past matches. Expand with mouse, touch or keyboard to see the latest match date and meaning. Teams with no qualifying details have no badge; an unavailable query is shown explicitly rather than implying no use.

The service authorises administrators, then makes one read-only parameterised aggregate query for the displayed team IDs. Existing `MatchResultTeamMeta` and `PlayerMatchPerformance` evidence is deduplicated by team/result. Empty saves, official scores alone, automatic squad selection, future/non-completed fixtures and details belonging to another fixture's teams do not count. The count is history for the exact team record, not a recent-use or latest-report-completeness claim. Similar names are not merged. Existing metadata has no submitter identity, so details entered on a team's behalf also count; this is not personal captain-attribution analytics. No AI report data is used.

The existing captain match-details save invalidates both admin pages after success. No changes to the save payload, results, permissions, charges, notifications or database schema. No flag to maintain and no historical data rewrite. The component is rendered by the owning pages; no DOM bridge or global navigation change.

`tests/admin-team-match-report-badge.test.cjs` runs the real reader, badge and owning pages with isolated I/O. CI additionally checks actual SQL against temporary tables in disposable localhost PostgreSQL, including meaningful/empty/malformed records, both teams, ratings, duplicate saves and exact-ID isolation. It repeats after the complete prebuild, verifies shared-source fingerprints, existing controls, critical contracts, types and build. Production submission and signed-in live rendering must be verified separately.
